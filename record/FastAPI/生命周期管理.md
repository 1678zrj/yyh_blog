### 问：FastAPI的生命周期管理到底是干嘛的？

简单来说，这个 `lifespan` 函数是用来管理 FastAPI 应用程序的“生命周期”的。

它的核心作用是让你能够精准地控制在**服务器启动之前**要做什么，以及在**服务器关闭之后**要清理什么。

你可以把它想象成一个“三明治”结构，而其中的 `yield` 就是中间的夹心（也就是你的应用运行的时间）。

### 🛠️ 它是怎么工作的？

利用 Python 的 `@asynccontextmanager` 装饰器，这个函数将应用生命周期一分为二：

1. **`yield` 之前的代码：** 在服务器启动准备接收请求之前运行（**启动阶段**）。
2. **`yield`：** 挂起函数，应用在这个时候正常运行，处理成千上万的用户请求。
3. **`yield` 之后的代码：** 当你按下 `Ctrl+C` 或者服务器停止时运行（**关闭/清理阶段**）。

### 💻 举个直观的例子

Python

```
from contextlib import asynccontextmanager
from fastapi import FastAPI

# 模拟一个数据库连接
class FakeDBContext:
    def connect(self): print("🔗 数据库已连接！")
    def close(self): print("🛑 数据库连接已断开！")

db = FakeDBContext()

@asynccontextmanager
async def lifespan(app: FastAPI):
    # ---------- 启动阶段 (Startup) ----------
    print("🚀 正在启动服务器...")
    db.connect()
    # 在这里可以加载重型资源，比如机器学习模型、建立数据库连接池等
    
    yield  # 🟢 服务器在这里交出控制权，开始接收并处理用户的 HTTP 请求
    
    # ---------- 关闭阶段 (Shutdown) ----------
    print("🧹 正在关闭服务器，准备清理资源...")
    db.close()
    # 在这里释放内存、关闭数据库连接、保存日志等

app = FastAPI(lifespan=lifespan)
```

### 💡 到底在什么实际场景下会用到它？

在真正的项目开发中，你几乎一定会用到它，主要用于以下场景：

1. **管理数据库连接池：** 你肯定不希望每次用户发来请求时都重新连接一次数据库（太慢了）。你需要在 `lifespan` 启动时建立一个全局的连接池，关闭时销毁它。
2. **加载机器学习模型：** AI 模型往往好几个 GB，加载需要几秒甚至十几秒。你应该在 `lifespan` 的启动阶段把它加载进内存，这样每个请求就能瞬间使用它进行预测了。
3. **启动后台任务/定时任务：** 比如启动一个后台循环去清理过期的数据。

### 🚀 高阶用法：共享状态 (State)

`lifespan` 还有一个非常强大的功能：**跨请求共享数据**。你可以通过 `yield` 返回一个字典，把重型资源（如模型、缓存客户端）注入到应用的 `state` 中，供所有的路由使用：

Python

```
ml_models = {}

@asynccontextmanager
async def lifespan(app: FastAPI):
    # 加载重型模型
    ml_models["my_model"] = "这是一个假装很复杂的AI模型"
    # 将包含模型的字典 yield 出去
    yield ml_models
    # 清理模型
    ml_models.clear()

app = FastAPI(lifespan=lifespan)

@app.get("/predict")
from fastapi import Request

async def predict(request: Request):
    # 在普通的路由里，可以直接拿来用！
    model = request.state.my_model
    return {"model_used": model}
```

**补充说明：** 如果你看过比较老旧的 FastAPI 教程，你可能会看到 `@app.on_event("startup")` 这种写法。`lifespan` 是 FastAPI 官方推荐的**最新替代方案**，因为它更符合 Python 标准，而且能够更好地在启动和关闭之间共享变量。

### 问：很好，那在开发过程中，已经有了创建数据库表并向表中插入测试数据的函数的情况下，如何在启动的时候进行该操作呢？并且是否要考虑数据库已存在的情况下就进行该操作，代码应该怎么写呢

在进行项目开发时，**必须考虑数据库或表已经存在的情况**。

因为在开发过程中，你会频繁地修改代码并重启服务器（例如使用 `--reload` 模式）。如果每次启动都不加判断地直接执行“创建”和“插入”操作，会导致以下后果：

1. **程序报错崩溃**：重复创建同名的表会导致数据库抛出异常。
2. **数据脏乱/重复**：每次重启都重复插入相同的测试数据，导致数据库中充斥着成百上千条重复记录。

### 💡 核心解决策略

1. **对于“创建表”**：使用主流 ORM（如 SQLAlchemy、Tortoise ORM、SQLModel 等）自带的“安全创建”方法。例如 SQLAlchemy 的 `Base.metadata.create_all(bind=engine)`，它在底层会自动执行 `CREATE TABLE IF NOT EXISTS`，**如果表已经存在，它会自动跳过，不会报错**。
2. **对于“插入测试数据”**：在插入之前，先执行一次查询（如 `COUNT` 或检查第一条记录）。**只有当表中完全没有数据时，才执行插入函数**；否则直接跳过。

### 💻 完整代码实现（以 SQLAlchemy 为例）

以下是完整的 FastAPI `lifespan` 代码架构：

```python
from contextlib import asynccontextmanager
from fastapi import FastAPI
from sqlalchemy import create_backend, create_engine, text, Column, Integer, String
from sqlalchemy.ext.declarative import declarative_base
from sqlalchemy.orm import sessionmaker

# 1. 数据库配置（这里以 SQLite 内存/文件数据库为例）
DATABASE_URL = "sqlite:///./tests.db"
engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)
Base = declarative_base()

# 2. 定义一个简单的模型
class User(Base):
    __tablename__ = "users"
    id = Column(Integer, primary_key=True, index=True)
    name = Column(String)

# 3. 核心：初始化数据库的函数
def init_db():
    # 策略 1：安全地创建所有表（如果表已存在，SQLAlchemy 会自动跳过）
    Base.metadata.create_all(bind=engine)
    
    # 创建一个独立的 session 用作初始化
    db = SessionLocal()
    try:
        # 策略 2：检查表中是否已经有数据，防止重复插入
        first_user = db.query(User).first()
        if first_user is None:
            print("📝 检测到数据库为空，正在插入测试数据...")
            test_users = [User(name="Alice"), User(name="Bob"), User(name="Charlie")]
            db.add_all(test_users)
            db.commit()
            print("✅ 测试数据插入成功！")
        else:
            print("⏭️ 数据库中已存在数据，跳过测试数据插入。")
    except Exception as e:
        db.rollback()
        print(f"❌ 初始化数据库失败: {e}")
    finally:
        db.close()

# 4. 定义生命周期管理器
@asynccontextmanager
async def lifespan(app: FastAPI):
    # ---------- [启动阶段] ----------
    print("🚀 服务器正在启动，开始检查并初始化数据库...")
    
    # 执行初始化逻辑（创建表 + 幂等插入数据）
    init_db() 
    
    yield  # 🟢 应用正常运行中...
    
    # ---------- [关闭阶段] ----------
    print("🧹 服务器正在关闭...")
    # 如果有连接池需要关闭，可以在这里操作

# 5. 挂载到 FastAPI 应用
app = FastAPI(lifespan=lifespan)

@app.get("/")
def read_root():
    return {"message": "Hello World"}
```
