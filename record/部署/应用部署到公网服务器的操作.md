## 一、 基础设施选型与网络链路

### 1. 域名与 DNS 解析 vs. ICP 备案

- **DNS 解析（免费自带）**：在任何域名服务商（Cloudflare、阿里云、腾讯云等）购买域名后，控制台均提供免费的权威 DNS 解析。通过添加 **A 记录** 将域名映射至服务器公网 IPv4，添加 **CNAME 记录** 做别名映射。
- **ICP 备案（法审流程，不自带）**：
  - **属地原则**：备案主体跟着**云服务器所在机房**走，与域名购买平台无关。若买大陆境内服务器，必须在服务器厂商系统提交身份证/执照、人脸识别并经管局审批（耗时 1~3 周），期间大陆机房的 80/443 端口被硬件防火墙强制阻断。
  - **免备案方案**：选择**中国香港或海外节点**，DNS 解析生效后即可直接通过 80/443 端口上线，**免去任何审批备案流程**。

### 2. 服务器规格与平台选型

- **首选推荐**：腾讯云 Lighthouse / 阿里云轻量应用服务器（**地域必选：中国香港**）。
- **预算与配置**：
  - **2核 2G（黄金起步）**：约 24 ~ 39 元/月，带宽通常为 20M ~ 30M BGP 直连。
  - **2核 4G（稳定充裕）**：约 60 ~ 80 元/月，内存充裕，可跑多容器栈与轻量 CI。
  - **网络延迟**：国内三大运营商直连延迟普遍在 **30 ~ 50 ms**，体验媲美境内机房。
- **安全组最小权限原则**：宿主机防火墙**仅放行 22 (SSH)、80 (HTTP)、443 (HTTPS)**，绝不向公网暴露 MySQL (3306)、Redis (6379) 等内部端口。

## 二、 硬件极限与服务承载上限

### 1. 2核 4G 的并发承载力评估

工程中的“并发”应拆解为 **QPS（每秒处理请求数）** 与 **同时在线用户数**：



| **负载类型**              | **预期 QPS 极限** | **核心制约瓶颈**                 | **典型场景**                       |
| ------------------------- | ----------------- | -------------------------------- | ---------------------------------- |
| **纯静态资源 / CDN 缓存** | 5,000 ~ 10,000+   | 网络带宽吞吐、TCP 连接数         | 静态前端、图片直链                 |
| **轻量异步 API / 缓存读** | 800 ~ 2,000       | CPU 单核调度、上下文切换         | Go / FastAPI (async) 查 Redis      |
| **常规数据库 CRUD**       | 100 ~ 400         | 磁盘 I/O、数据库连接池、ORM 解析 | 用户登录鉴权、分页列表查询         |
| **密集计算 / 复杂报表**   | 10 ~ 50           | 2 颗 vCPU 算力彻底打满           | 大文件本地压缩、加密计算、复杂联表 |

- **同时在线用户估算**：

  按用户平均每 10 秒触发一次 API 计算：

  $$\text{同时在线人数} \approx \text{稳定 QPS (约 200)} \times 10\text{ 秒} \approx 2,000\text{ 人}$$

  对应日活（DAU）数万以内的系统，2核 4G 架构完全能够平稳承载。

### 2. 30Mbps 带宽的物理瓶颈与防爆指南

- **换算公式**：$30 \text{ Mbps} \div 8 = 3.75 \text{ MB/s}$（出网总吞吐上限）。

- **瓶颈场景**：API 返回 100KB 未压缩 JSON 时，仅需 37 个并发即可将带宽彻底堵死；若有 3 人同时下载大文件，单人速度会被腰斩至 1.2 MB/s。

- **系统内存防线（Swap 交换分区）**：小机器必须在开机后立即挂载 4GB Swap，防止 Docker 构建或数据库瞬时消耗打满物理内存触发 Linux OOM 杀进程：

  Bash

  ```
  sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile
  sudo mkswap /swapfile && sudo swapon /swapfile
  echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
  sudo sysctl vm.swappiness=20
  ```

## 三、 Docker & Compose 编排核心逻辑

`docker-compose.yml` 的本质是**容器基础设施编排器**，负责将原本零散的 `docker run` 参数以声明式语法统一管理，不负责解析具体应用内部的专有语法。



- **业务代码容器（必须自定义 Dockerfile）**：
  - **必须打包**：保证“不可变基础设施”与跨平台一致性，避免宿主机与 Linux 容器底层 C 依赖冲突（如 `sharp`、`bcrypt`）。
  - **多阶段构建（Multi-stage）**：在构建镜像中编译代码（Node/Go/Java），在纯净的运行时镜像中仅复制构建产物，极致缩小镜像体积。
- **基础组件容器（纯官方镜像 + 挂载）**：
  - Nginx、MySQL、Redis 直接拉取官方镜像。
  - 采用 `volumes:` 将宿主机维护的配置文件（如 `./nginx.conf`）单向挂载覆盖容器内路径，通过 `environment:` 注入数据库账号密码。
- **内部通信机制**：
  - Compose 会自动分配内部独立子网。
  - 容器间无需绑定真实 IP，直接以**服务名（Service Name）作为域名通信**（如后端配置数据库地址为 `mysql:3306`）。

## 四、 本地文件服务与 Cloudflare 边缘缓存破局

针对本地已实现的断点续传/分片上传代码，**完全不需要推翻重写**，只需在架构最外层挂载 Cloudflare 代理。



### 1. 流量与架构完全解耦

- **解耦原则**：业务系统在 VPS 内自成闭环，即使剥离 CDN，系统依然能独立运行。
- **上传与下载链路差异**：
  - **入网（上传）**：云厂商通常不限速或配额极高，本地断点续传切片（2MB~5MB）在入网通道下秒级传输，体验稳定。
  - **出网（下载）**：受制于 30Mbps，必须通过 CDN 缓存将流量卸载至边缘节点。

### 2. Cloudflare 缓存运行原理

- **Cache Key（缓存唯一标识）**：
  - 默认由 `协议 + 域名 + 请求路径 + 查询参数` 拼接而成。
  - **Cloudflare 不会主动计算源站文件的 MD5/SHA256 哈希值**，只要请求 URL 未变且未过期，直接从边缘节点吐出数据。
- **文件版本更新策略**：
  - **ContentHash（推荐）**：构建时将内容哈希写入文件名（如 `app.v1.2.a8f9.zip`），URL 变化导致 Cache Key 自动失效并触发回源，无任何延迟。
  - **缓存清理（暴力）**：若采用同名文件覆盖，必须在 Cloudflare 控制台手动执行 **Purge Cache**。
  - **304 协商缓存**：Nginx 开启 `etag on;`，当 TTL 到期后，Cloudflare 会发送 `If-None-Match` 向源站探测。文件未动时 Nginx 仅返回 0 字节的 304 响应头，边缘节点继续续期。
- **核心限制**：Cloudflare 免费版**单文件缓存上限为 512 MB**，低于 512MB 可被完整持久化缓存，超出部分将直通源站消耗服务器带宽。

## 五、 生产级 Nginx 配置与性能调优模板

Nginx

```
server {
    listen 80;
    server_name yourdomain.com;

    # 1. 解除本地大文件分片上传体积限制
    client_max_body_size 0;

    # 2. 动态业务 API 反代
    location /api/ {
        proxy_pass http://backend_service:8000/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 3. 本地大文件静态分发与 CDN 缓存注入
    location /downloads/ {
        alias /data/storage/downloads/;

        # --- 零拷贝与网络传输优化 ---
        sendfile on;          # 内核态空间直接读取并发送，不占用户空间内存
        tcp_nopush on;        # 填满 TCP 报文后再发送，优化大包传输
        tcp_nodelay on;       # 保证 ACK 即时响应

        # --- 内存保护 ---
        directio 10m;         # 超过 10MB 的文件绕过系统 PageCache，防止小内存服务器挤爆
        directio_alignment 4096;

        # --- 原生断点续传支持 ---
        max_ranges 10;        # 支持 HTTP 206 Partial Content 分片下载
        etag on;              # 生成文件指纹配合 CDN 协商缓存

        # --- 缓存控制核心响应头 ---
        # public: 允许 CDN 代理缓存
        # max-age=604800: 用户浏览器本地缓存 7 天
        # s-maxage=2592000: Cloudflare 边缘节点强制持久化缓存 30 天
        # immutable: 告知浏览器在到期前绝不重复发包验证
        add_header Cache-Control "public, max-age=604800, s-maxage=2592000, immutable" always;

        # 跨域支持（供前端 Axios/Fetch 读取下载进度）
        add_header Access-Control-Allow-Origin * always;
        add_header Access-Control-Allow-Methods "GET, HEAD, OPTIONS" always;
        add_header Access-Control-Expose-Headers "Content-Length, Content-Range" always;
    }
}
```

```
    # 2. 动态业务 API 反代
    location /api/ {
        # 使用 Docker 内部 DNS 直接请求服务名 backend
        proxy_pass http://backend:8000/;
        
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 延长超时，适配耗时较长的上传接口
        proxy_connect_timeout 60s;
        proxy_read_timeout 120s;
    }

    # 3. 本地大文件静态分发 (配合 Cloudflare 边缘缓存)
    location /downloads/ {
        # 对应 gateway 容器内挂载的绝对路径
        alias /data/storage/downloads/;

        sendfile on;
        tcp_nopush on;
        tcp_nodelay on;

        # 大于 10MB 绕过 PageCache，保护 2G/4G 服务器物理内存
        directio 10m;
        directio_alignment 4096;

        # 原生分片断点续传支持
        max_ranges 10;
        etag on;

        # 告知 Cloudflare 边缘缓存 30 天，客户端缓存 7 天
        add_header Cache-Control "public, max-age=604800, s-maxage=2592000, immutable" always;
        add_header Access-Control-Allow-Origin * always;
    }
}
```
