# Git新增一个版本是怎么做到的

在 Git 中，新增一个版本（即一次提交）是通过以下步骤实现的：

------

### 1. **文件状态跟踪**

Git 首先会对文件进行状态跟踪，主要分为以下三种状态：

- **已修改（Modified）**：文件在工作区中被编辑。
- **已暂存（Staged）**：文件被添加到暂存区，准备提交。
- **已提交（Committed）**：文件的快照存储在本地仓库中。

------

### 2. **新增版本的操作流程**

1. **修改文件**
   - 在工作区修改文件内容。
   - Git 通过文件的哈希值检测文件是否有改动。
2. **添加到暂存区**
   - 使用 `git add` 命令将修改后的文件添加到暂存区。
   - Git 会对每个被 `git add` 的文件生成一个新的对象（Blob 对象），并记录它们的哈希值。
   - 暂存区会生成一个索引文件，保存当前快照的状态。
3. **提交到本地仓库**
   - 使用 `git commit` 命令，将暂存区的内容打包为一个新的版本（Commit）。
   - Git 生成一个提交对象（Commit 对象），包含以下信息：
     - **快照信息**：指向暂存区的索引。
     - **元信息**：提交者、提交时间等。
     - **父提交引用**：指向上一个版本，形成提交历史链。
     - **提交说明**：由用户提供的说明信息。
4. **版本存储**
   - Git 将提交对象存储到 `.git/objects` 目录中。
   - 提交对象的哈希值（SHA-1）作为唯一标识。
   - 分支的 HEAD 指针更新到新版本，指向最新的提交。

------

### 3. **Git 内部的对象模型**

Git 使用以下几种对象存储版本信息：

1. **Blob 对象**：存储文件的内容（快照）。
2. **Tree 对象**：描述文件和目录的结构，记录文件名、权限和对应的 Blob 哈希值。
3. **Commit 对象**：记录版本信息，指向一个 Tree 对象，并包含父提交引用。

新增一个版本时，Git 会：

- 创建新的 Blob 对象（如果文件内容发生变化）。
- 生成一个 Tree 对象，指向所有相关的 Blob 对象。
- 创建一个新的 Commit 对象，指向该 Tree 对象，并关联父提交。

------

### 4. **示例：新增一个版本**

假设你在项目中修改了一个文件 `file.txt`，以下是新增版本的过程：

#### (1) 修改文件

编辑文件后，查看状态：

```bash
git status
```

#### (2) 添加到暂存区

```bash
git add file.txt
```

这会将文件的快照添加到暂存区。

#### (3) 提交到本地仓库

```bash
git commit -m "Updated file.txt with new content"
```

Git 会生成一个新的提交对象，并更新 HEAD。

#### (4) 查看提交历史

```bash
git log
```

你会看到新增的版本记录，包括提交哈希值、提交说明等。

------

### 5. **新增版本的核心特点**

- **不可变性**：每个版本的内容由哈希值唯一标识，提交后的版本不可篡改。
- **完整性验证**：Git 通过 SHA-1 哈希值校验文件内容的完整性。
- **高效性**：只存储文件的增量（内容变化部分），未改动的文件引用原来的对象。

------

总结起来，Git 通过对文件内容的快照和对象模型的管理，快速、高效地新增版本，并维护整个项目的版本历史。
