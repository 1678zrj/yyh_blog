```python
from datetime import datetime, timedelta
from jose import jwt
from passlib.context import CryptContext
from app.core.config import settings

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")


def verify_password(plain_password: str, hashed_password: str) -> bool:
    return pwd_context.verify(plain_password, hashed_password)

def get_password_hash(password: str) -> str:
    return pwd_context.hash(password)



def create_access_token(data: dict) -> str:
    to_encode = data.copy()
    expire = datetime.utcnow() + timedelta(minutes=settings.ACCESS_TOKEN_EXPIRE_MINUTES)
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, settings.SECRET_KEY, algorithm="HS256")
```

### 问：这段代码from app.core.config import settings在编译器里报红了，怎么解决？

这是一个典型的 **IDE（PyCharm）路径识别问题**。

虽然你的代码写的是 `from app.core.config import settings`，这在 FastAPI 的标准运行环境下（通常是在 `backend` 目录下运行）是完全正确的，但在 PyCharm 眼里，它默认把你的项目根目录 `training-platform` 当作起点，所以它找不到 `app` 这个包（因为它在 `backend` 里面）。

你可以通过以下两种方式解决：

### 方法一：设置源码目录（推荐 ✅）

这是最规范的解决方法，告诉 PyCharm：“我的 Python 代码是从 `backend` 这个文件夹开始算的”。

1. 在左侧的项目文件树中，**右键点击** `backend` 文件夹。
2. 选择 **Mark Directory as**（将目录标记为）。
3. 选择 **Sources Root**（源代码根目录）。

**效果：** `backend` 文件夹会变成蓝色，IDE 里的红色波浪线会立即消失，且代码跳转功能（Ctrl+左键）也能正常工作了。

------

### 方法二：使用相对导入（备选）

由于 `security.py` 和 `config.py` 都在同一个 `core` 文件夹下，你可以直接把导入语句改成相对路径：

Python

```
# 修改前
from app.core.config import settings

# 修改后
from .config import settings
```

**注意：** 虽然这样也能消除报红，但我更推荐 **方法一**。因为设置好 Sources Root 后，你以后在项目的任何地方写 `from app...` 都能获得完美的智能提示，这对于大型项目（像你在做的这个训练平台）非常有帮助。

### 补充说明

当你运行这个项目时，确保你的运行目录是在 `backend` 下，或者将 `PYTHONPATH` 包含了 `backend` 目录，否则 Python 解释器也会报 `ModuleNotFoundError: No module named 'app'`。如果你是用 Docker 部署，通常会在 Dockerfile 里设置 `WORKDIR /app/backend` 或类似路径来保证导入正确。
