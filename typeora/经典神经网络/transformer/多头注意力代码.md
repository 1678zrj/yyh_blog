```python
import torch
import math, copy
import torch.nn.functional as F
import torch.nn as nn


def clone(module,N):
    return nn.ModuleList(copy.deepcopy(module) for _ in range(N))



def attention(query: torch.Tensor, key: torch.Tensor, value: torch.Tensor, mask=None, dropout=None):
    d_k = query.size(-1)
    scores = torch.matmul(query, key.transpose(-2,-1)) / math.sqrt(d_k)

    if mask is not None:
        scores = scores.masked_fill(mask==0,-1e6)

    p_attn = F.softmax(scores, dim=-1)
    if dropout is not None:
        p_attn = dropout(p_attn)
    return torch.matmul(p_attn, value), p_attn



class MultiHeadedAttention(nn.Module):
    def __init__(self, h, d_model, dropout=0.1):
        super(MultiHeadedAttention, self).__init__()
        assert d_model % h == 0                             
        self.d_k = d_model // h
        self.h = h
        self.linears = clones(nn.Linear(d_model, d_model), 4)
        self.attn = None
        self.dropout = nn.Dropout(p=dropout)

    def forward(self, query, key, value, mask=None):
        if mask is not None:
            # Same mask applied to all h heads.
            mask = mask.unsqueeze(1)
        nbatches = query.size(0)

        # 1) Do all the linear projections in batch from d_model => h x d_k
        query, key, value = [l(x).view(nbatches, -1, self.h, self.d_k).transpose(1, 2) for l, x in zip(self.linears, (query, key, value))]
        # 2) Apply attention on all the projected vectors in batch.
        x, self.attn = attention(query, key, value, mask=mask, dropout=self.dropout)

        # 3) "Concat" using a view and apply a final linear.
        x = x.transpose(1, 2).contiguous().view(nbatches, -1, self.h * self.d_k)
        return self.linears[-1](x)
```

你提到的这行代码是多头注意力机制（`MultiHeadedAttention`）的核心操作之一，它将输入的 `query`、`key` 和 `value` 做线性变换后**拆分成多个 head**。我们来**逐步拆解理解**这一行：

------

## 🔍 拆解过程

我们一步一步分析：

------

### 第一步：`zip(self.linears, (query, key, value))`

这表示：

- `self.linears`: 是 4 个 `nn.Linear(d_model, d_model)` 组成的列表（通过 `clones()` 构建）。
  - 前 3 个分别用于：`query`, `key`, `value` 的线性投影；
  - 第 4 个用于最后输出 projection。

所以 `zip(self.linears, (query, key, value))` 对应的是：

```python
(l0, query), (l1, key), (l2, value)
```

------

### 第二步：`l(x)`

每一个 `x`（即 `query`, `key`, `value`）都被对应的线性层 `l` 投影到 `d_model` 维度。

```python
l(x) → shape: [batch_size, seq_len, d_model]
```

------

### 第三步：`.view(nbatches, -1, self.h, self.d_k)`

将 `d_model` 拆成 `h` 个头，每个维度为 `d_k`。即：

```python
[batch_size, seq_len, d_model] → [batch_size, seq_len, h, d_k]
```

再 rearrange 一下：

```python
.view(batch_size, seq_len, h, d_k)
```

------

### 第四步：`.transpose(1, 2)`

交换第 1 和第 2 个维度，使 head 维度提前：

```python
[batch_size, seq_len, h, d_k] → [batch_size, h, seq_len, d_k]
```

这就是 **多头注意力需要的输入格式**，每个 batch 中有 `h` 个 head，每个 head 自己有一套 `[seq_len, d_k]` 向量表示。

------

## ✅ 最终结果

```python
query, key, value = [
    l(x).view(batch_size, seq_len, h, d_k).transpose(1, 2)
    for l, x in zip(self.linears, (query, key, value))
]
```

每个输出都是：

```python
shape: [batch_size, h, seq_len, d_k]
```

这是传给 `scaled dot-product attention` 的标准格式。

| 步骤     | 操作                                                         |
| -------- | ------------------------------------------------------------ |
| 1️⃣        | 对 query/key/value 做线性变换（相当于学习一个 projection）   |
| 2️⃣        | 将投影后的向量 reshape 成多个 attention head 的形式          |
| 3️⃣        | 调整维度顺序，以便并行计算多个 head 的 attention             |
| 最终输出 | `[batch_size, h, seq_len, d_k]` 的张量，适用于多头注意力计算 |

### 这个zip()这么智能吗？self.linears和(query, key, value)长度明明不一样

这个疑问提得非常好！看起来 `zip(self.linears, (query, key, value))` 的两个输入长度似乎不匹配——`self.linears` 明明有 **4 个** `Linear` 层，而 `(query, key, value)` 只有 **3 个张量**，那为什么不会出错？

------

## ✅ 关键点：`zip()` 只遍历最短长度！

在 Python 中，`zip(a, b)` 默认会截断到两个序列中**最短**的那个长度。

### 示例如下：

```python
a = [1, 2, 3, 4]
b = ['a', 'b', 'c']

list(zip(a, b))  
# 结果：[(1, 'a'), (2, 'b'), (3, 'c')]  —— 第 4 个元素被忽略了
```

### 在你的代码中：

```python
zip(self.linears, (query, key, value))
```

假设：

- `self.linears = [Linear_0, Linear_1, Linear_2, Linear_3]`（共 4 个）
- `(query, key, value)` 只有 3 个张量

那么 `zip(...)` 的结果就是：

```python
[
    (Linear_0, query),
    (Linear_1, key),
    (Linear_2, value)
]
```

第 4 个 `Linear`（即 `Linear_3`）根本不会被用在这一行。

------

## 🤔 那多出来的第 4 个 Linear 是干嘛的？

这是关键点：

```python
self.linears = clones(nn.Linear(d_model, d_model), 4)
```

这 4 个 `Linear` 分别用于：

1. `Linear_0`: 用于 `query`
2. `Linear_1`: 用于 `key`
3. `Linear_2`: 用于 `value`
4. `Linear_3`: 用于最终 `concat` 后的输出 projection（即最后那行代码）：

```python
return self.linears[-1](x)
```

所以虽然 `zip` 只用了前 3 个 `Linear`，但最后一个是单独在 return 时使用的。

| ----------------------------------------------------- | ------------------------------------------------------------ |
| `zip(self.linears, (query, key, value))` 为啥没报错？ | 因为 `zip` 默认只取最短长度的项，即前三个 `Linear` 配对用，剩下的忽略 |

## 还有这行代码 x = x.transpose(1, 2).contiguous().view(nbatches, -1, self.h * self.d_k)的contiguous()是干嘛的


其中的 `.contiguous()` 看起来很神秘，但它**非常关键**，特别是在 PyTorch 中使用 `.view()` 前。

------

## ✅ `contiguous()` 的作用是什么？

**简答：**
 `contiguous()` 的作用是：**返回一个内存连续的 Tensor 副本**，用于支持后续的 `.view()` 操作。

------

## 🧠 背景知识：PyTorch 中的内存布局

在 PyTorch 中，张量的元素在内存中通常是按行或按列顺序排列的。某些操作（比如 `.transpose()` 或 `.permute()`）并**不会重新排布内存**，而只是返回一个**新的“视图”**（view），指向原始数据的不同排列。

例如：

```python
a = torch.randn(2, 3)
b = a.transpose(0, 1)  # 改变了维度顺序，但不改变内存
```

此时 `b` 是非连续的（non-contiguous）。

------

## ❗ 为什么 `.view()` 要求内存连续？

`.view()` 本质上是直接在内存上“重新解释”维度，不会进行复制或移动数据。

如果你用 `.view()` 去 reshape 一个 **非连续的张量**，PyTorch 就会报错：

```
RuntimeError: view size is not compatible with input tensor's size and stride
```

------

## ✅ `.contiguous()` 就是解决这个问题的方法

调用 `.contiguous()` 会让 PyTorch：

1. 把张量的内容**复制**到一块新的**连续内存中**；
2. 返回这个新张量，可以安全使用 `.view()`。

------

## 🔍 结合你的代码解释：

```python
x = x.transpose(1, 2)                          # 转置后的张量可能是非连续的
x = x.contiguous()                             # 保证它的内存是连续的
x = x.view(nbatches, -1, self.h * self.d_k)    # reshape 成最后输出形状
```

此时 `x` 的 shape 从 `[batch_size, h, seq_len, d_k]` → `[batch_size, seq_len, h * d_k]`

即从多头拼接回一个大向量。

------

## 🧪 示例代码对比

```python
a = torch.randn(2, 3, 4)
b = a.transpose(1, 2)  # b 是非 contiguous 的

print(b.is_contiguous())  # False
try:
    b.view(2, 12)
except RuntimeError as e:
    print(e)  # 报错！

# 修复方式
c = b.contiguous().view(2, 12)
print(c.shape)  # OK
```

------

## ✅ 总结

| 项目                   | 内容                                                         |
| ---------------------- | ------------------------------------------------------------ |
| `.contiguous()` 的作用 | 保证张量在内存中是连续的                                     |
| 为什么需要它           | `.view()` 只能用于连续内存的张量                             |
| 什么时候常用           | 在 `transpose()`, `permute()` 后紧跟 `view()` 时             |
| 替代方案               | 如果你不想用 `contiguous()`，可以用 `.reshape()`（会自动处理） |

### 张量使用了什么方法后在内存中一定是连续的，使用了什么方法后在内存中一定是不连续的呢

这是一个非常细致且有价值的问题！下面我将从实践角度总结哪些 **操作会让张量变为非连续（non-contiguous）**，以及哪些操作 **一定会返回连续（contiguous）** 的张量。

------

## ✅ 一定会让张量变为 **非连续** 的操作：

这些操作**只是改变维度顺序或切片方式**，不会改变底层内存顺序，因此返回的张量是 **非连续的**：

| 操作                         | 说明                                      |
| ---------------------------- | ----------------------------------------- |
| `transpose(dim0, dim1)`      | 交换两个维度                              |
| `permute(*dims)`             | 任意维度重新排列                          |
| `narrow(dim, start, length)` | 对张量按某维做切片                        |
| `select(dim, index)`         | 选择某维的一个值，返回低维张量            |
| `as_strided()`               | 返回一个新张量，仅修改 stride，不修改数据 |
| `unfold()`                   | 类似滑动窗口，生成不连续片段              |

------

### 🔍 举例：

```python
a = torch.randn(2, 3, 4)
b = a.transpose(1, 2)
print(b.is_contiguous())  # False
c = a.permute(2, 0, 1)
print(c.is_contiguous())  # False
```

------

## ✅ 一定会让张量变为 **连续** 的操作：

这些操作会**强制复制数据**，返回新的连续内存张量：

| 操作                       | 说明                                       |
| -------------------------- | ------------------------------------------ |
| `.contiguous()`            | 手动让张量变连续                           |
| `.clone()`                 | 深拷贝张量，新的张量是连续的               |
| `.reshape()`（某些情况下） | 会自动生成连续内存（等价于 view + contig） |
| `.view()`（前提是连续）    | 如果张量本身是连续的，则 view 保持连续     |

------

### 🔍 举例：

```python
a = torch.randn(2, 3, 4).transpose(1, 2)  # 非连续
b = a.contiguous()  # 强制变为连续
print(b.is_contiguous())  # True

c = a.clone()  # 复制时也会是连续的
print(c.is_contiguous())  # True
```

------

## 🧠 补充：如何查看张量的内存布局？

你可以使用 `.stride()` 方法查看张量每一维的步长（step size）：

```python
a = torch.randn(2, 3, 4)
print(a.stride())  # 通常是 (12, 4, 1)

b = a.transpose(1, 2)
print(b.stride())  # 会变成 (12, 1, 4) —— 非连续
```

连续张量的 stride 是按行主顺序排列的（高维度跳得远，低维度跳得近）。

------

## ✅ 总结表格

| 操作类型        | 是否保证连续           | 备注说明                     |
| --------------- | ---------------------- | ---------------------------- |
| `transpose()`   | ❌ 非连续               | 常用于 attention             |
| `permute()`     | ❌ 非连续               | 调整维度顺序                 |
| `narrow()`      | ❌ 非连续               | 截取子区间                   |
| `.contiguous()` | ✅ 连续                 | 常用于配合 `.view()`         |
| `.clone()`      | ✅ 连续                 | 新分配内存                   |
| `.reshape()`    | ✅（多数情况）          | 自动处理内存，但可能复制数据 |
| `.view()`       | ❌/✅ 取决于输入是否连续 |                              |

------

如果你在调试模型时看到 `.view()` 报错，**第一反应就是检查是否需要 `.contiguous()`**。

### 接下来我想知道矩阵相乘的规则，特别是像（B,H,L,D)和（B,H,D,L)这样形状的矩阵相乘

这是 Transformer 等深度学习模型中非常常见的一类矩阵乘法问题。下面我会**系统讲解矩阵相乘的规则**，并**专门分析你提到的形状 `(B, H, L, D)` 和 `(B, H, D, L)` 的相乘**是怎么回事。

------

## 📘 一、基础：矩阵乘法规则

两个矩阵要能相乘，其**内维**必须相等：

```text
A: (..., M, K)
B: (..., K, N)
输出: (..., M, N)
```

即：最后两个维度执行标准的矩阵乘法（`K` 对应），前面维度要么是相同的，要么是 broadcast-compatible（PyTorch 支持 broadcasting）。

------

## 📘 二、示例：你提到的形状 `(B, H, L, D)` 和 `(B, H, D, L)`

我们先说明：

- `(B, H, L, D)`：表示有 `B` 个 batch，每个有 `H` 个 attention head，每个 head 有 `L` 个 query，query 向量维度为 `D`。
- `(B, H, D, L)`：可能是 key 的转置，原始 key 是 `(B, H, L, D)`，转置后用于计算注意力得分。

我们要做的操作是：

```python
# query: (B, H, L, D)
# key.transpose(-2, -1): (B, H, D, L)

attn_scores = torch.matmul(query, key.transpose(-2, -1))  # => (B, H, L, L)
```

### ✅ 为什么可以相乘？

因为：

- query 的最后两个维度是 `(L, D)`
- key.T 的最后两个维度是 `(D, L)`
- `D` 与 `D` 对齐（内维相等），符合矩阵乘法规则

乘法结果形状为：

```python
(B, H, L, L)
```

这正是**注意力分数矩阵**，表示每个 query（长度为 L）对每个 key（也是长度 L）的打分。

------

## 📌 三、总结：通用乘法规则（以 batch 和 head 为前缀）

| 参与相乘的两个张量              | 含义                 | 最后两个维度        | 相乘后形状     |
| ------------------------------- | -------------------- | ------------------- | -------------- |
| `(B, H, L, D)` × `(B, H, D, L)` | query × keyT         | `(L, D)` × `(D, L)` | `(B, H, L, L)` |
| `(B, H, L, L)` × `(B, H, L, D)` | attn_weights × value | `(L, L)` × `(L, D)` | `(B, H, L, D)` |

------

## 🔍 附加说明

- `matmul` 自动广播前面的维度 `(B, H)`，并对最后两维做矩阵乘法。
- 如果你想看类似向量 × 向量、向量 × 矩阵的行为，可参考官方文档：[PyTorch `matmul`](https://pytorch.org/docs/stable/generated/torch.matmul.html)

------

## ✅ 示例代码

```python

B, H, L, D = 2, 4, 5, 8
query = torch.randn(B, H, L, D)
key = torch.randn(B, H, L, D)

# 计算注意力分数
attn_scores = torch.matmul(query, key.transpose(-2, -1))  # (B, H, L, L)

```

你可以这么理解：

- `query`: shape = `(B, H, L, D)`
   → 可以看作 `B * H` 个 `L × D` 矩阵
- `key.transpose(-2, -1)`: shape = `(B, H, D, L)`
   → 可以看作 `B * H` 个 `D × L` 矩阵

**矩阵相乘规则匹配：**

- 每个 `L × D` 矩阵 × 对应的 `D × L` 矩阵 → 结果为 `L × L`
- 总共 `B * H` 组，逐对相乘，**一一对应**（即第 `i` 个和第 `i` 个相乘）

这就是所谓的 **batched matrix multiplication**，`torch.matmul` 就是这么处理的。

------

## ✅ 二、你可以手动 reshape 来验证这个过程：

```python
import torch

B, H, L, D = 2, 3, 4, 5

query = torch.randn(B, H, L, D)
key = torch.randn(B, H, L, D)

# reshape 为 BH × L × D
q = query.reshape(B * H, L, D)
k = key.reshape(B * H, L, D)

# key 转置为 BH × D × L
kt = k.transpose(1, 2)

# batched matrix multiplication: (BH, L, D) @ (BH, D, L) -> (BH, L, L)
attn_scores = torch.bmm(q, kt)

# 还原回 (B, H, L, L)
attn_scores = attn_scores.view(B, H, L, L)
print(attn_scores.shape)  # 输出: torch.Size([2, 3, 4, 4])
```

结果与你使用 `torch.matmul(query, key.transpose(-2, -1))` 是完全一致的。

------

## ✅ 三、结论

> 将 `(B, H, L, D)` 和 `(B, H, D, L)` 看作 `BH` 个二维矩阵时，**确实是按顺序一一对应**地执行矩阵乘法。PyTorch 中的 `torch.matmul` 或 `torch.bmm` 就是这么实现的。

如果你要手动实现注意力层或调试中间结果，这个视角非常有帮助 👍

如你需要，我也可以演示这种矩阵相乘在注意力权重计算、上下文向量聚合中的全过程。

### 是不是就类似于两层for循环变量二维矩阵中的每个矩阵元素呢，然后(i,j)和(i,j)的矩阵相乘，位于(j,i)和(j,i)的矩阵相乘这样

是的，你的类比非常准确！我们可以把这个 **多维张量的矩阵相乘**想象成**嵌套的两层 for 循环**，具体如下：

------

### 🎯 问题背景

以两个张量：

- `A`: shape = `(B, H, L, D)`，可以看作 `B × H` 个 `L × D` 矩阵
- `B`: shape = `(B, H, D, L)`，可以看作 `B × H` 个 `D × L` 矩阵（也就是转置后的 key）

你希望执行：

```python
output = torch.matmul(A, B)  # or torch.matmul(query, key.transpose(-2, -1))
```

------

### 🔁 等价的嵌套 for 循环（类比）

```python
output = torch.zeros(B, H, L, L)

for b in range(B):
    for h in range(H):
        a_matrix = A[b, h]      # shape (L, D)
        b_matrix = B[b, h]      # shape (D, L)
        out = a_matrix @ b_matrix  # shape (L, L)
        output[b, h] = out
```

你可以看到：

- `A[b, h] @ B[b, h]` → `L × L` 矩阵
- 每对 `(b, h)` 是一一对应地计算的

------

### ✅ 类比总结

> 就像你说的：
>
> > 是不是就类似于两层for循环变量二维矩阵中的每个矩阵元素呢，然后(i,j)和(i,j)的矩阵相乘……

完全正确。更准确说：

- 每个 `(b, h)` 对应一个 `L × D` 和一个 `D × L` 矩阵相乘
- PyTorch 自动广播并并行处理了这些乘法，相当于你手写 for 循环中的一一匹配过程
