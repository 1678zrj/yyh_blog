## 问：我发现Pytorch定义的方法好像都不会修改张量本身

你观察得非常准确！在 **PyTorch 中大多数的张量操作方法默认**确实是**不修改原始张量本身的**，而是返回一个新的张量。也就是说，除非你显式地赋值回去，例如：

```python
x = x.squeeze()
```

否则原始 `x` 是不变的。

------

## ✅ 一、为什么 PyTorch 默认不修改原始张量？

这是为了 **避免副作用（side effect）**，提高代码的可读性和可维护性。你可以放心地把某个张量传给多个操作，不用担心这些操作会悄悄修改原始数据。

------

## ✅ 二、如果要修改原张量怎么办？

PyTorch 提供了对应的**原地操作（in-place operation）**，通常是方法名后面加一个 **下划线 `_`**。

### 常见原地操作示例：

| 操作     | 原地方法           | 非原地方法    | 说明                            |
| -------- | ------------------ | ------------- | ------------------------------- |
| 取绝对值 | `x.abs_()`         | `x.abs()`     | 修改原张量                      |
| 加法     | `x.add_(y)`        | `x.add(y)`    | 修改原张量                      |
| squeeze  | ❌没有 `squeeze_()` | `x.squeeze()` | ❗`squeeze` 没有原地版本，需赋值 |
| relu     | `x.relu_()`        | `x.relu()`    | 原地 ReLU 激活                  |

```python
x = torch.tensor([-1.0, 2.0, -3.0])
x.abs_()
print(x)  # tensor([1.0, 2.0, 3.0])
```

------

## ❗ 特别说明：某些操作不提供 in-place 版本

像 `squeeze()`、`unsqueeze()` 这类操作，**没有 `squeeze_()` 这样的原地版本**，因为它们可能需要重新分配内存或影响计算图结构，这类操作推荐直接赋值覆盖：

```python
x = x.squeeze()
```

------

## ✅ 三、怎么判断一个方法是不是原地操作？

- 如果方法名后有 **下划线 `_`**：表示原地操作，会修改张量本身。
- 没有下划线的：都是返回新张量的非原地操作。

```python
x = torch.tensor([1.0, 2.0])
y = x.add(3)    # 非原地，x unchanged
z = x.add_(3)   # 原地，x modified
```

------

## ✅ 四、为何要谨慎使用原地操作？

原地操作会影响：

1. **反向传播**：可能会破坏 autograd 计算图，导致梯度计算出错（尤其在中间变量上使用）。
2. **调试困难**：原地改变量可能引起“数据污染”，不易追踪 bug。

## 问：你说的避免副作用，副作用指什么

很好，这个问题抓得很准。你在问“副作用指什么”，这是编程中一个**基础但非常重要的概念**。我们来详细解释一下。

------

## ✅ 什么是副作用（Side Effect）？

**副作用**指的是：一个函数或操作在执行过程中，**除了返回值之外，还修改了程序的其他部分状态**，比如：

- 修改了函数外部的变量（例如输入参数、全局变量、对象属性）
- 写入了文件或数据库
- 打印输出
- 网络请求
- 抛出异常（有时也视为副作用）

简而言之：**函数偷偷干了“额外的事情”，这些事情不是它返回值体现出来的**。

------

## 🧠 举个例子：有副作用 vs 无副作用

### 🟥 有副作用的函数：

```python
def add_and_modify(lst, val):
    lst.append(val)  # 修改了传入的列表，这是副作用！
    return sum(lst)
my_list = [1, 2]
result = add_and_modify(my_list, 3)
print(result)       # 输出 6
print(my_list)      # 输出 [1, 2, 3] —— 外部变量被改了！
```

> 这个函数“偷偷”修改了你传进去的 `my_list`，这就是副作用。

------

### ✅ 无副作用的函数（纯函数）：

```python
def pure_add(lst, val):
    new_list = lst + [val]
    return sum(new_list)
my_list = [1, 2]
result = pure_add(my_list, 3)
print(result)       # 输出 6
print(my_list)      # 输出 [1, 2] —— 没有被改
```

> 这个函数没有改变外部变量，行为完全可预测，就是一个“纯函数”，**无副作用**。

------

## 🧪 为什么要避免副作用？

| 问题       | 说明                                                         |
| ---------- | ------------------------------------------------------------ |
| ❓不可预测  | 副作用使得函数不再“输入唯一决定输出”                         |
| 🐛 易出 bug | 一个地方改了数据，另一个地方可能被影响，bug 更隐蔽           |
| 🧩 难测试   | 函数不再只依赖输入，还依赖全局状态或其他对象                 |
| ♻️ 自动微分 | PyTorch 中 `autograd` 机制依赖函数“纯净”地构建计算图，原地改变量可能破坏图结构 |

------

## 🤔 那副作用是不是一定不好？

不是。**副作用是现实世界编程的必要组成部分**，比如你要：

- 读取文件（副作用）
- 打印日志（副作用）
- 网络通信（副作用）

但是我们希望：

> ✅ 在设计模型、数值计算、张量操作这类“纯逻辑”的函数时，尽量避免副作用，提高可维护性和可组合性。

------

## 🔁 回到 PyTorch：为何 `x.squeeze()` 不带副作用？

- 为了让张量操作更安全、更“纯”
- 避免你不小心改掉了中间变量（可能被多个地方引用）
- 兼容 autograd 的自动求导系统

所以：

```python
y = x.squeeze()  # 返回新的张量
```

如果你真的想改原张量，那你就**明确地赋值**或者用原地操作（带 `_` 的方法）：

```python
x = x.squeeze()     # 可读性强，副作用明确
x.add_(1)           # 明确地改了 x
```

------

## 🔚 总结一句话：

> **副作用**就是函数除了返回值外，**还悄悄地改了外部世界或状态**。PyTorch 默认避免副作用，是为了让代码更安全、可控、易于调试和自动求导。
