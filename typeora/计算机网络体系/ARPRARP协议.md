#  ARP/RARP协议

**ARP**（Address Resolution Protocol，地址解析协议）和**RARP**（Reverse Address Resolution Protocol，反向地址解析协议）是两种用于不同层次网络通信的协议，旨在解决如何在网络中通过IP地址和MAC地址之间进行映射的问题。

### 1. **ARP（Address Resolution Protocol）**

ARP是用来在局域网中将IP地址解析为对应的物理地址（即MAC地址）的协议。ARP工作在网络层和数据链路层之间，它能够确保数据包在局域网内被正确地传送给目标设备。

#### **ARP的工作原理**

当一个设备（如计算机、路由器等）知道某个IP地址，但不知该地址对应的MAC地址时，它会使用ARP协议来进行查找。

1. **ARP请求**：设备会广播一个ARP请求包到网络中，询问“谁拥有这个IP地址？”。ARP请求包包含了发送者的IP地址和MAC地址，以及目标的IP地址。
2. **ARP响应**：拥有该目标IP地址的设备会收到ARP请求，并发送一个ARP响应包，告诉请求者它的MAC地址。
3. 发送者根据收到的ARP响应缓存目标设备的MAC地址，并将数据包直接发送到目标设备的MAC地址。

#### **ARP报文结构**

ARP报文包含以下内容：

- **硬件类型（Hardware Type）**：表示网络硬件的类型（如以太网是1）。
- **协议类型（Protocol Type）**：表示协议类型，通常为IP协议（0x0800）。
- **硬件地址长度（Hardware Address Length）**：以太网地址长度通常是6字节（48位）。
- **协议地址长度（Protocol Address Length）**：IPv4地址长度通常是4字节（32位）。
- **操作（Operation）**：表示请求或应答。1是ARP请求，2是ARP响应。
- **发送者硬件地址（Sender Hardware Address）**：发送方的MAC地址。
- **发送者协议地址（Sender Protocol Address）**：发送方的IP地址。
- **目标硬件地址（Target Hardware Address）**：目标设备的MAC地址（对于请求是空的）。
- **目标协议地址（Target Protocol Address）**：目标设备的IP地址。

#### **ARP缓存**

设备通常会将IP地址和对应的MAC地址保存在本地的**ARP缓存**中，避免频繁发送ARP请求。ARP缓存会在一定时间后过期，并需要重新请求。

### 2. **RARP（Reverse Address Resolution Protocol）**

RARP是ARP的反向协议，用于通过设备的MAC地址来查询其IP地址。RARP协议通常在设备不知道自己IP地址时使用，尤其是在启动时。

#### **RARP的工作原理**

RARP协议的工作过程与ARP类似，但它的目的是从设备的MAC地址反向解析出IP地址。

1. **RARP请求**：当一台设备（通常是没有存储IP地址的设备，如无盘工作站）启动时，它通过广播发送RARP请求，要求知道与自己的MAC地址对应的IP地址。
2. **RARP响应**：网络中的RARP服务器收到请求后，会查找其数据库，找到对应的IP地址，然后将该IP地址返回给请求设备。
3. 设备使用返回的IP地址配置自身，从而可以加入到网络中进行通信。

#### **RARP的局限性**

RARP协议存在一些局限性：

- **需要RARP服务器**：RARP需要专门的RARP服务器来响应请求，但这种服务器并不普遍存在。
- **不能支持动态IP分配**：RARP只能为设备提供一个固定的IP地址，不能支持像DHCP（动态主机配置协议）那样的动态IP地址分配。

### 3. **ARP和RARP的对比**

| 特性         | ARP                                 | RARP                              |
| ------------ | ----------------------------------- | --------------------------------- |
| 目的         | 通过IP地址解析MAC地址               | 通过MAC地址反向解析IP地址         |
| 工作方式     | 查找目标设备的MAC地址               | 查找目标设备的IP地址              |
| 典型应用场景 | 在网络中已知IP地址时查找MAC地址     | 在设备启动时根据MAC地址获取IP地址 |
| 协议层次     | 网络层和数据链路层之间              | 数据链路层                        |
| 使用的协议   | ARP协议                             | RARP协议                          |
| 现代替代方案 | ARP仍然广泛使用，通常用于局域网通信 | 已被DHCP等协议取代                |

### 4. **ARP和RARP的现代替代协议**

- **ARP**：仍然广泛使用于IPv4网络中，用于解析局域网内的设备之间的IP与MAC地址映射。
- **RARP**：由于其局限性，已经被**DHCP**（动态主机配置协议）所取代。DHCP不仅可以根据MAC地址分配IP地址，还能动态管理IP地址，支持更多的功能和配置。

### 5. **总结**

- **ARP**：用于通过已知的IP地址查找MAC地址，是局域网中设备通信的关键协议。
- **RARP**：用于通过已知的MAC地址查找IP地址，曾经用于无盘工作站等设备的IP获取，但现在已被更灵活的DHCP协议所取代。
