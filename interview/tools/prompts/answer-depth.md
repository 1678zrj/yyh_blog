# 八股答案规范（v2）：原理驱动，而不是结论驱动

## 要解决的问题

读者的原话：

> 感觉缺少一些底层原理说明**为什么问题应该这么回答**，就导致这些知识点看着像是让人死记硬背的，
> 而不是真正地理解。

所以问题不是"写得不够长"，而是**答案是凭空给出的结论**。三条信息的缺席让答案只能背：

| 缺席的东西 | 表现 | 后果 |
| --- | --- | --- |
| **第一性约束** | 直接说"应该用 B+ 树"，不说磁盘以页为单位交换数据 | 不知道前提，换个场景就答错 |
| **推导过程** | 把结论平铺成要点，不展示怎么推出来的 | 只能记结论，答不出"为什么不是别的" |
| **反事实** | 不说"如果 X 变了会怎样" | 无法验证自己是否真懂 |

**判断标准**（唯一标准）：

> 读完这段答案，读者能不能**不看原文、自己把结论重新推一遍**？
> 只能复述 = 不合格；能推导 = 合格。

## 每道题的标准骨架

```
### Q1. <题面>

**一句话回答**：结论（30 秒能说完；不带口号）

**底层原理**：为什么世界是这个样子。
    写第一性约束：硬件特性 / 协议规定 / 语言语义 / 数学性质 / 成本模型。
    这里必须能回答「为什么不是别的方案」——约束排除了别的可能。

**从原理推答案**：把结论一步步推出来。
    用「因为…所以…」的链条，读者看到这一步能自己补出下一步。
    关键节点配具体数字/参数/代码/命令（这些是证据，不是主角）。

**换个前提会怎样**：反事实。
    如果某个前提变了（数据量小 10 倍 / 单机 / 读多写少 / 允许最终一致），
    答案会变成什么。这一节是"真理解"的试金石，也是面试官最爱追的地方。

**常见追问**：面试官顺着问的第 2、3 层，附答案

**容易答错的边界**：什么情况下前面的结论不成立

**来源**：……
```

### 两类知识要区别对待

| 类型 | 例子 | 怎么写 |
| --- | --- | --- |
| **推理型**（可推导） | 索引为什么选 B+ 树、为什么要三次握手、为什么需要 MVCC | 必须给完整推导链，让读者能自己推 |
| **记忆型**（必须背） | 命令名、配置项、协议字段、状态码 | 承认它只能记，但给出**记忆的抓手**：为什么是这个名字/这个数量/这个顺序，用原理把零散信息串成一条线 |

**不许把推理型知识写成记忆型**（这是当前最大的毛病）。

## 绝对禁止

- **四字口号**：`动态识别 + 分层承载`、`三层防线`、`双写一致`——口号是"背诵感"的头号来源。
  必须先说清"发生了什么事"，再给做法。
- **凭空结论**：任何"应该用 X"前面必须有约束推导
- **套话**：「提升性能」「保证可靠」「更加灵活」——要么给数字，要么给判据
- **名词堆砌**：只列 A、B、C 而不说"因为 A 所以不用 B"
- **编造数字**：查不到就写「量级参考」或 `> 存疑：…`
- **把本规范当填空模板**：骨架是下限，能合并就合并，但**原理与反事实两节不能省**

## 篇幅

- 普通题 600~1200 字；高频核心题 1500~2500 字
- 不设总字数上限；每一段都要有信息增量，宁可短也不灌水

## 结构约束（硬性，不能动）

专区前端按标签着色、按题目分组，骨架必须保持：

- `### Qn.` 三级标题、题号连续
- 四个核心标签保留且顺序不变：`**一句话回答**` → `**展开**` → `**常见追问**` → `**容易答错的边界**`
  - 说明：`**展开**` 这一节内部用新的三节结构承载（`**底层原理**` / `**从原理推答案**` / `**换个前提会怎样**`），
    这样前端不用改、也能被"自测模式"整体折叠
- 允许新增加粗小标签：`**底层原理**`、`**从原理推答案**`、`**换个前提会怎样**`、`**记忆锚点**`、`**判据**`
- **列表项前必须留空行**（Python-Markdown 硬要求，否则渲染成一大段）

## 对照示例

**坏（凭空结论）**：

> **展开**：
> - 索引用 B+ 树，因为查询效率高、适合范围查询。
> - 不用 B 树是因为 B 树非叶子节点也存数据。

**好（原理驱动）**：

> **底层原理**：索引要解决的问题是**减少磁盘 I/O 次数**，而磁盘的最小交换单位是**页**（InnoDB 默认 16 KB）。
> 一次 I/O 只能搬一页，所以"一页里能装多少路分支"直接决定了树有多高，树高就是 I/O 次数。
> 这就是唯一的约束——不是"哪个数据结构更高级"。
>
> **从原理推答案**：按这个约束逐个排除候选：
> - **哈希**：等值 O(1)，但哈希把相邻键打散，范围查询和排序直接不可用，而 `WHERE id > 100` 这类查询在业务里极常见 → 排除。
> - **BST / 红黑树**：出度只有 2，树高约 log₂N。1 亿行要 27 层 = 27 次 I/O → 排除。
> - **B 树**：多路，但**非叶子节点也存数据行**，同样 16 KB 页能放的 key 变少，扇出小、树更高，
>   且命中位置不固定（可能在内节点就返回）→ 作为磁盘索引不如 B+ 树。
> - **B+ 树**：非叶子只存 key，16 KB 页能放几百个 key → 三层就能覆盖千万级；
>   数据全在叶子且叶子串成双向链表 → 范围查询找到起点后顺序扫，配合预读。
>
> **换个前提会怎样**：
> - 如果数据能全放内存（如 MEMORY 引擎、Redis），树高不再是瓶颈，**哈希索引反而更合适**（O(1)）。
> - 如果只做等值查询、绝无范围查询，哈希也可以。
> - 所以"B+ 树"这个答案的前提是**磁盘 + 存在范围查询**；面试时把这个前提说出来，
>   比直接背结论有说服力得多。

## 落地方式

1. 每章一个「编辑代理」，**必须先读 `interview/raw/` 下对应语料**，把命令/参数/数字/现象挖出来当证据
2. 重写时先问自己："这道题的第一性约束是什么？"——写不出约束，说明还没到能改的程度
3. 抽查标准：随机抽 3 题，看能否**不看原文自己推一遍**
